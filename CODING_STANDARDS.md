# Coding standards

## Layout map

The source root is `src/`. Two runtime directories never import each other: `src/router/` runs as the router process, the CLI and the harness hooks, all from one entry, and `src/pi/` runs inside pi's process. `src/shared/` is the contract between them. ADRs 0003 and 0010 record why.

### The folder rule

A file holds at most 600 lines and a folder at most 20 entries. Past either cap, the file becomes a folder named for its concept, with what its callers use in `index.ts` and its parts as modules inside, never a suffixed sibling such as `doctor-codex.ts`. Code outside a folder imports only its `index.ts`. Place each part by the first question that fits:

1. Does it know no feature and no outside system, and own no state? It goes to `primitives/`.
2. Does it write a durable value or know an outside system? It goes to `client/`.
3. Is it a concept with its own interface? It becomes a folder inside, with its tests.

An exception is a line in `size-limits.txt` with its count and the reason.

## Rules that need judgment

- **A gate that fails caught something.** Fix the code. When a rule is wrong for this repo, take it to the owner with what it flags here and your pick. A rule goes off only with the owner's approval, or when files kept outside the repo prove that no spelling satisfies it and another rule together. Its line in `.oxlintrc.jsonc` names the reason.
- **A ban covers all of `src/` and lifts only for its owner.** The `src/**` block in `.oxlintrc.jsonc` and the owner rules in `.dependency-cruiser.json` hold in every folder. An owner gets one override that lifts exactly its API, with its ledger reason, and a line in the `bans-owners` fixture for each ban it does not own. Ban the root a shortcut starts from, such as the global, not one spelling of it. A ban whose owner file does not exist yet waits only while another gate rejects the API, a rule the owner approved.
- **Each durable value has one writer.** A new file, store or setting gets its `client/` file before a feature reads or writes it, and every caller goes through that file.
- **New product work adds files.** A command is a file in `src/router/features/cli/`, or a file in the folder of its concept, and one entry in the command list it belongs to. The list parses flags into contract types, and the command is a plain Effect function that takes them.
- **A contract lives in `src/shared/`.** Both runtimes encode and decode with the same schema, and the command names pi spells come from the same file.
- **`bun run test` stays fast under load.** A test that builds the plugin or starts a process is a `*.e2e.test.ts`, and a test that holds code to a wall-clock bound is a `*.perf.test.ts`. `bun run test` runs neither.
- **A test drives the code through its interface.** Replace a `client/` service with a test layer, and assert what a caller or an outside system observes.
- **Use the glossary's words.** Name code, tests and messages with the terms in `GLOSSARY.md`.
- **Vendored code keeps its upstream.** `tools/oxlint/anti-slop/` changes only by rerunning the upstream install script its `UPSTREAM.md` names.
